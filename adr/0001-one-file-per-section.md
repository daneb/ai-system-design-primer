# ADR 0001: One file per section, README as index

- Status: accepted
- Date: 2026-11-01

## Context

The original primer is a single 1,839-line README. That made it easy to read and to translate, but it
has no per-section metadata, every change touches one large file, and stale sections cannot be found or
rewritten in isolation.

## Decision

Each section is its own Markdown file under `docs/<part>/`, named `<id>-<slug>.md`, with YAML front
matter. `README.md` is an index whose table of contents and progress table are generated by
`scripts/primer.py readme`.

## Consequences

- Frontier sections can be rewritten without touching the stable core.
- Per-section ownership and review dates become possible (ADR 0002).
- A single-page or EPUB edition needs a build step. Not built yet.
