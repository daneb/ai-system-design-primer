# 0.2 Inside a model call: prefill, decode and reasoning

![The prompt's tokens go through prefill all at once, which is limited by arithmetic and builds the KV cache; then decode writes one token per step, reading all the weights and the KV cache each time, which is limited by memory speed; a reasoning model writes hidden reasoning tokens before the visible answer.](../../images/0.2-inside-a-model-call.svg)
<!-- source: images/src/0.2-inside-a-model-call.mmd; render with scripts/diagrams.py -->

A model call has two phases that behave very differently. Knowing them explains four things you are
billed and judged on. Output tokens cost more than input tokens. Long answers are slow while long
prompts are fairly quick. Long contexts use a lot of memory. And reasoning models can cost many times
more than their visible answer suggests.

You don't need the mathematics. You need the shape, because it drives prices, latency targets and
capacity plans in [2.7](../2-trade-offs/2.7-throughput-vs-latency.md) and
[3.8](../3-components/3.8-serving-internals.md).

## Key terms

- **Parameters (weights):** the billions of numbers learned in training; every token passes through all of them in a typical model.
- **Attention:** the step where each token's representation is updated using all earlier tokens; it is how the model uses its context.
- **Prefill:** the first phase: the whole prompt is processed at once, producing the first output token.
- **Decode:** the second phase: one token per step, each step reading every weight from memory.
- **KV cache:** saved attention keys and values for every token so far, so earlier tokens aren't recomputed.
- **Reasoning tokens:** hidden working a reasoning model writes before its answer; billed as output.

More in the [glossary](../5-appendix/5.6-glossary.md).

## How it works

### What the model is

- **A large function.** Each token is turned into a list of numbers (an embedding), then passed
  through dozens of layers. An 8-billion-parameter model stored at 16 bits is 16 GB of weights.
- **About two arithmetic operations per parameter per token.** Most models today send every token
  through every weight, so work grows with model size times tokens.
- **Attention ties tokens together.** Every token looks back at every earlier token. That is why the
  model can use anything in its context, and why longer contexts cost more.

### Two phases

- **Prefill reads the prompt in parallel.** The hardware's arithmetic units stay busy, so it is fast
  per token. It sets the time to first token (TTFT).
- **Decode writes one token at a time.** Each step must read all the weights and the whole KV cache
  from memory to produce a single token. Memory speed, not arithmetic, is the limit. It sets the time
  per output token (TPOT).
- **The KV cache saves recomputation and costs memory.** Without it, every new token would reprocess
  the whole sequence. For an 8-billion-parameter model it takes about 131 KB per token, so long
  contexts and many users fill the accelerator ([3.8](../3-components/3.8-serving-internals.md)).
- **Batching rescues decode.** One read of the weights can serve many users' next tokens at once,
  which is why providers can sell output at all ([2.7](../2-trade-offs/2.7-throughput-vs-latency.md)).

### Why output costs more

- In [Lab 0.2](../../labs/0.2-inside-a-model-call/README.md), prefill ran at 25,000 tokens per second.
  Decode for one user ran at 123, about 200 times more accelerator time per token.
- Batching 64 users narrowed the gap to about 6 times. Providers price output several times higher
  than input, which matches.
- **Rule of thumb:** cutting output tokens saves more time and money than cutting the same number of
  input tokens.

### Reasoning models

- **They think in tokens.** A reasoning model writes hidden working before its answer. Anthropic,
  OpenAI and Google all bill these tokens as output, and they count against the context window and the
  output limit.
- **You set a budget.** Providers expose a thinking budget or an effort level, and report reasoning
  tokens separately in the usage figures. Earlier turns' reasoning is usually dropped from the context.
- **Sampling settings may not apply.** Several providers fix or reject temperature and top-p when
  reasoning is on ([0.1](0.1-tokens-context-and-sampling.md)).

## Example

A support assistant answers in about 300 tokens after a 2,000-token prompt, on a server batching 16
users. In [Lab 0.2](../../labs/0.2-inside-a-model-call/README.md) the call finishes in about 3.7
seconds. The team tries a reasoning model at its default effort, which writes about 4,000 hidden
tokens per answer.

With output priced at five times input, each call now costs 6.7 times as much. It takes about 52
seconds instead of 3.7, and the user sees nothing until the reasoning ends. Accuracy on their eval
rose only for the 10% of questions that needed several policy rules combined. So the team routes those
questions to the reasoning model and keeps a fast model for the rest
([3.7](../3-components/3.7-model-layer.md)).

## What it means for design

- Measure TTFT and TPOT separately; they have different causes and different fixes.
- Stream answers, so users see the first tokens while decode continues.
- Cap output length, and prefer short structured answers where a person won't read prose.
- Use reasoning where problems need several steps; set its budget, and turn it off for extraction,
  classification and formatting.
- Plan self-hosted capacity from KV cache memory as well as weights.

## Disadvantages and pitfalls

- **Estimating cost from the visible answer.** Hidden reasoning can be many times longer.
- **Treating latency as one number.** A slow first token and a slow stream need different fixes.
- **Long contexts by default.** Every extra token of context slows each decode step and uses memory.
- **Leaving reasoning on everywhere.** Simple tasks pay the reasoning cost and gain nothing.

## Flashcards

Q: What are the two phases of a model call, and what limits each?
A: Prefill processes the whole prompt in parallel and is limited by arithmetic; decode writes one token per step and is limited by memory speed.

Q: Which phase sets time to first token, and which sets streaming speed?
A: Prefill sets time to first token (TTFT); decode sets time per output token (TPOT).

Q: What does the KV cache save, and what does it cost?
A: It saves recomputing earlier tokens on every step; it costs accelerator memory for every token of every active request.

Q: Why do output tokens cost more than input tokens?
A: Each output token needs its own decode step, which reads all the weights from memory; prompt tokens are processed many at once.

Q: How are reasoning tokens billed?
A: As output tokens, even though you don't see them; they also count against the context window and output limit.

Q: When should you turn reasoning off?
A: For extraction, classification, formatting and other single-step tasks, where it adds cost and latency without improving accuracy.
