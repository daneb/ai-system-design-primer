# 3.3 Context engineering

```mermaid
flowchart LR
  S[Sources:<br/>instructions, tools,<br/>history, retrieved data,<br/>memory] --> Sel[Select]
  Sel --> Cmp[Compress:<br/>clear, summarise]
  Cmp --> Ord[Order]
  Ord --> W[Working context<br/>for this call]
  W --> M[Model]
  M -->|new turn, tool result| S
```

Context engineering is deciding what goes into the model's context window on every call. It grew out
of prompt engineering: the prompt is still there, but in a multi-turn agent it is a small part of what
the model sees. Tool definitions, conversation history, tool results, retrieved documents and memory all
compete for the same window.

The window is a budget, not a bin. Models get less reliable as the context grows, even far below the
limit; researchers call this *context rot*. Anthropic's guidance is to find the smallest set of
high-signal tokens that gets the result you want.

## What goes in the window

- **Instructions.** Clear and at the right level: specific enough to guide, general enough not to break
  on cases you didn't foresee.
- **Tools.** Each definition costs tokens on every call. Fewer, distinct tools; if a person can't say
  which tool fits, neither can the model.
- **Examples.** A few varied ones, rather than a long list of edge cases.
- **History.** What the user said and what the agent did.
- **Tool results and retrieved data.** Usually the largest part, and the first to go stale.
- **Memory.** Facts loaded from outside the window ([3.11](3.11-memory.md)).

## How to keep it small

- **Load just in time.** Keep references (file paths, IDs, queries) and fetch the content with a tool
  when needed, instead of loading everything up front ([3.5](3.5-agentic-retrieval.md)).
- **Clear old tool results.** Once the agent has acted on a result, it rarely needs the raw text again.
- **Trim.** Keep the last *N* turns. Simple and predictable, but forgets early instructions.
- **Summarise (compact).** Replace old turns with a summary, keep recent turns verbatim. Keeps more,
  but each pass can drop details.
- **Take notes.** The agent writes key facts, decisions and progress to a file outside the window and
  reads them back.
- **Isolate with sub-agents.** A sub-agent explores in its own clean context and returns a short
  summary ([3.10](3.10-multi-agent-and-protocols.md)).
- **Order with care.** Models use the start and end of a long context better than the middle (*lost in
  the middle*). Put key instructions and evidence at the edges.

## When to use

- Any agent that runs more than a few turns or calls tools that return large outputs.
- Long conversations where cost and latency grow with every turn.
- Before reaching for a bigger context window: curating usually beats filling.

## When to avoid

- Single-call tasks that fit easily. Don't build compaction for a prompt that is 3k tokens.
- Summarising audit-relevant history you must keep verbatim. Store the full record outside the window
  and compact only the working copy.

## Disadvantages

- **Every strategy forgets something.** Trimming loses early facts; clearing loses facts that lived in
  tool results; summaries drop details at random and compound across passes.
- **Changing the start of the context breaks prompt caching** ([3.13](3.13-caching.md)), so frequent
  edits can cost more than they save.
- **Summaries can carry errors forward**, or clean them up, depending on the summariser.
- **Harder to debug.** You need to log what the model actually saw on each call ([3.16](3.16-observability.md)).

## Flashcards

Q: What is context engineering?
A: Choosing what goes into the model's context window on each call (instructions, tools, history, tool results, retrieved data, memory) to get the result with the fewest high-signal tokens.

Q: What is context rot?
A: The drop in model reliability as input length grows, even well below the context limit.

Q: What does "lost in the middle" mean, and what do you do about it?
A: Models use information at the start and end of a long context better than the middle; put key instructions and evidence at the edges.

Q: Trimming vs summarising history?
A: Trimming keeps the last N turns and forgets older ones entirely; summarising replaces old turns with a summary, keeping more but losing details with each pass.

Q: In a tool-heavy agent, what usually takes most of the context?
A: Tool results. Clearing old ones saves the most tokens while keeping what the user said.

Q: How does structured note-taking help?
A: The agent writes key facts and progress to a store outside the window and reads them back, so they survive clearing and compaction.
