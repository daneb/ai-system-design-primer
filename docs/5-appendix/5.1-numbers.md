# 5.1 Numbers every AI engineer should know

The classic primer has latency numbers every programmer should know. These are their AI equivalents:
the ratios and orders of magnitude that let you do a back-of-the-envelope estimate
([1 Method](../1-method/1-method.md)) without looking anything up.

Ratios last longer than prices, so prices appear only as multipliers. Every figure has a source and an
"as of" date. Figures marked **derived** are this primer's own arithmetic or labs; the working is in
the linked lab. Re-verify anything older than its section's review date.

## Tokens

| Number | Value | As of | Source |
|---|---|---|---|
| Characters per token (English) | ≈ 4 | Nov 2026 | [OpenAI](https://help.openai.com/en/articles/4936856) |
| Words per token (English) | ≈ 0.75 (100 tokens ≈ 75 words) | Nov 2026 | OpenAI |
| A page of text | ≈ 500 tokens (≈ 375 words) | derived | from the two rows above |
| Same text, different model | different token count; compare cost per task, not per token | Nov 2026 | OpenAI |

Other languages and code tokenise differently; measure with your model's tokenizer.

## Flashcards

Q: Roughly how many English words is 1,000 tokens?
A: About 750 (one token ≈ ¾ of a word ≈ 4 characters).

Q: Which halves latency: halving input or halving output tokens?
A: Halving output tokens. Halving input saves only a few percent.

Q: What does batch processing cost relative to standard calls?
A: About half, in exchange for results within hours.

Q: How many bytes per parameter for 16-bit, 8-bit and 4-bit weights?
A: 2, 1 and 0.5.

Q: How precise is a pass rate measured on 100 cases?
A: About ±8 percentage points (95% interval at an 80% pass rate).

Q: Below roughly what corpus size can you skip retrieval and put everything in the prompt?
A: About 200,000 tokens (≈ 500 pages), per Anthropic.
