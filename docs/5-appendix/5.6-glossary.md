# 5.6 Glossary

Grows with every section. Each term links to the section that explains it.

| Term | Meaning | Section |
|---|---|---|
| A2A (Agent2Agent) | Open protocol for one agent to discover another and delegate tasks to it without seeing its internals; Linux Foundation project | [3.10](../3-components/3.10-multi-agent-and-protocols.md) |
| Agent | A model that decides which tools to call, in a loop, until a task is done | [3.9](../3-components/3.9-workflows-and-agents.md) |
| Agent card | A2A's JSON description of an agent (skills, endpoints, security), served at a well-known URL | [3.10](../3-components/3.10-multi-agent-and-protocols.md) |
| Agentic retrieval | The model decides what to search for, reads results and searches again until it has enough; also agentic RAG or agentic search | [3.5](../3-components/3.5-agentic-retrieval.md) |
| Agents Rule of Two | Meta's rule: a session should have at most two of untrusted input, sensitive access, and the ability to change state or communicate out | [2.4](../2-trade-offs/2.4-capability-vs-security.md) |
| AI gateway | A reverse proxy every model call passes through, handling auth, token quotas, routing, fallback, policy and telemetry | [3.1](../3-components/3.1-ai-gateway-and-router.md) |
| ANN (approximate nearest neighbour) | Search that skips most of a vector collection for speed, accepting that it may miss some true nearest neighbours | [3.6](../3-components/3.6-vector-stores.md) |
| Back-pressure | Slowing or refusing new work when a queue grows faster than it can be drained | [3.14](../3-components/3.14-asynchronism.md) |
| Base rate (guardrails) | How common attacks are in real traffic; when low, most blocks from an imperfect detector are false alarms | [3.2](../3-components/3.2-input-guardrails.md) |
| Batch API | Asynchronous processing of many requests at about half price, returned within hours | [2.1](../2-trade-offs/2.1-cost-quality-latency.md) |
| BM25 | A keyword ranking function: scores documents by query-term frequency, weighted by term rarity and normalised for length | [3.4](../3-components/3.4-retrieval-pipeline.md) |
| CaMeL | Google DeepMind design that turns the user's request into a program and tracks where each value came from, blocking policy-violating tool calls | [2.4](../2-trade-offs/2.4-capability-vs-security.md) |
| Capability eval / regression eval | Hard tasks that show where to improve / tasks that already work and gate releases near 100% | [3.15](../3-components/3.15-evals.md) |
| Chunk | A passage cut from a document for indexing and retrieval | [3.4](../3-components/3.4-retrieval-pipeline.md) |
| Chunked prefill | Splitting a long prompt's prefill into chunks interleaved with other requests' decode steps | [3.8](../3-components/3.8-serving-internals.md) |
| Circuit breaker | Stops sending traffic to a failing backend for a while, then tries again | [3.1](../3-components/3.1-ai-gateway-and-router.md) |
| Compaction | Replacing older conversation turns with a model-written summary while keeping recent turns verbatim | [3.3](../3-components/3.3-context-engineering.md) |
| Complete mediation | Checking every request to a downstream system against policy, rather than trusting the caller (here, the model) | [3.17](../3-components/3.17-security.md) |
| Complexity ladder | Single call → workflow → single agent → multi-agent; start at the lowest rung that meets the quality bar | [1](../1-method/1-method.md) |
| Constrained decoding / structured outputs | Generation restricted so only tokens valid for a JSON Schema can be produced; guarantees shape, not content | [3.12](../3-components/3.12-output-guardrails.md) |
| Context engineering | Choosing what goes into the context window on each call: instructions, tools, history, tool results, retrieved data, memory | [3.3](../3-components/3.3-context-engineering.md) |
| Context rot | Falling accuracy as input length grows, well before the context window is full | [3.7](../3-components/3.7-model-layer.md) |
| Context stuffing | Putting a whole knowledge base in the prompt instead of retrieving passages; also called long-context prompting | [2.3](../2-trade-offs/2.3-context-vs-retrieval.md) |
| Contextual retrieval | Prepending model-written context about a chunk's place in its document before embedding and indexing it | [3.4](../3-components/3.4-retrieval-pipeline.md) |
| Continuous batching | Re-forming the batch at every decode step so finished requests leave and new ones join (also iteration-level scheduling, in-flight batching) | [2.7](../2-trade-offs/2.7-throughput-vs-latency.md) |
| Corrective RAG (CRAG) | Grading retrieved documents before answering and rewriting the query or trying another source when they are weak | [3.5](../3-components/3.5-agentic-retrieval.md) |
| Criteria drift | Evaluation criteria changing as people read more outputs; criteria can't all be fixed in advance | [3.15](../3-components/3.15-evals.md) |
| Decode | The second phase: one token per step, each step limited by reading weights and cache from memory | [3.8](../3-components/3.8-serving-internals.md) |
| Denial of wallet | Abuse that drives up pay-per-token costs rather than taking a service down (OWASP LLM10) | [3.1](../3-components/3.1-ai-gateway-and-router.md) |
| Direct / indirect prompt injection | Attack written by the user / attack hidden in content the system reads (documents, emails, tool results) | [3.2](../3-components/3.2-input-guardrails.md) |
| Disaggregation (prefill/decode) | Running prefill and decode on separate accelerators and transferring the KV cache between them | [3.8](../3-components/3.8-serving-internals.md) |
| Distillation | Training a small student model on a large teacher model's answers to match it on one task | [3.18](../3-components/3.18-model-adaptation.md) |
| Dual LLM pattern | A privileged model plans and calls tools; a quarantined model with no tools reads untrusted content and returns references | [2.4](../2-trade-offs/2.4-capability-vs-security.md) |
| Durable execution | A workflow engine records each completed step so a failed or crashed run resumes from its last checkpoint | [3.14](../3-components/3.14-asynchronism.md) |
| Embedding | A vector produced by a model so that inputs with similar meaning are close together | [3.6](../3-components/3.6-vector-stores.md) |
| Error amplification | How much a mistake by one agent grows by the final result; higher for unchecked parallel agents than for an orchestrator that validates | [2.5](../2-trade-offs/2.5-single-vs-multi-agent.md) |
| Eval | A repeatable measurement of output quality against agreed criteria | [3.15](../3-components/3.15-evals.md) |
| Evaluator-optimizer | One call drafts, another checks against clear criteria and sends it back with feedback, up to a round limit | [3.9](../3-components/3.9-workflows-and-agents.md) |
| Excessive agency | OWASP LLM06: damage from an LLM's actions caused by too much functionality, permission or autonomy | [2.4](../2-trade-offs/2.4-capability-vs-security.md) |
| Faithfulness / groundedness | Whether an answer is supported by the context it was given | [3.15](../3-components/3.15-evals.md) |
| Fallback chain | An ordered list of alternative deployments or providers to try when the first fails | [3.1](../3-components/3.1-ai-gateway-and-router.md) |
| Fine-tuning | Further training a model's weights on your own examples to change its behaviour | [2.6](../2-trade-offs/2.6-prompt-rag-finetune.md) |
| Goodput | Requests per second served within latency targets (TTFT and TPOT), rather than raw throughput | [2.7](../2-trade-offs/2.7-throughput-vs-latency.md) |
| Grounding check | A check that each claim in an answer is supported by the sources it was given | [3.12](../3-components/3.12-output-guardrails.md) |
| Guardrail | A check on what goes into or comes out of a model, with an action: allow, mask, block or flag | [3.2](../3-components/3.2-input-guardrails.md) |
| Handoff | A triage agent passes the conversation to a specialist agent, which owns it from then on | [3.9](../3-components/3.9-workflows-and-agents.md) |
| Harmlessness screen | A small, fast model with constrained output used to pre-screen input (Anthropic's term) | [3.2](../3-components/3.2-input-guardrails.md) |
| HNSW | Hierarchical Navigable Small World: a layered graph index for ANN search; the common default | [3.6](../3-components/3.6-vector-stores.md) |
| Hybrid search | Running keyword and vector search together and fusing the results | [3.4](../3-components/3.4-retrieval-pipeline.md) |
| Idempotency key | A unique caller-supplied request ID that lets a retried action take effect only once | [3.14](../3-components/3.14-asynchronism.md) |
| Improper output handling | Using model output unsafely downstream (rendering, SQL, shell), enabling XSS, injection or code execution (OWASP LLM05) | [3.12](../3-components/3.12-output-guardrails.md) |
| IVF | Inverted file index: clusters vectors and searches only the clusters nearest the query | [3.6](../3-components/3.6-vector-stores.md) |
| Jitter | Randomising retry waits so clients that failed together don't retry together | [3.14](../3-components/3.14-asynchronism.md) |
| Knowledge injection | Getting facts a model lacks into its answers, via retrieval (works well) or fine-tuning (works poorly) | [2.6](../2-trade-offs/2.6-prompt-rag-finetune.md) |
| KV cache | Stored attention keys and values for every processed token, so they aren't recomputed; grows with tokens and concurrent requests | [3.8](../3-components/3.8-serving-internals.md) |
| Lethal trifecta | Private data + untrusted content + external communication in one system; enables exfiltration via prompt injection | [2.4](../2-trade-offs/2.4-capability-vs-security.md) |
| Lethal trifecta | Willison's term: private data, untrusted content and external communication in one agent, enabling data theft by injection | [2.4](../2-trade-offs/2.4-capability-vs-security.md) |
| LLM-as-judge | Using a model to grade another model's output against a rubric or by pairwise comparison | [3.15](../3-components/3.15-evals.md) |
| LoRA | Parameter-efficient fine-tuning that freezes the base model and trains small low-rank adapter matrices | [3.18](../3-components/3.18-model-adaptation.md) |
| Lost in the middle | Models use information at the start and end of a long context better than the middle, giving a U-shaped accuracy curve | [3.3](../3-components/3.3-context-engineering.md) |
| Manager pattern | A central agent calls specialist agents as tools and keeps ownership of the answer | [3.9](../3-components/3.9-workflows-and-agents.md) |
| MCP (Model Context Protocol) | Open protocol connecting AI apps to tools, resources and prompts exposed by servers; Linux Foundation project | [3.10](../3-components/3.10-multi-agent-and-protocols.md) |
| MITRE ATLAS | ATT&CK-style knowledge base of adversary tactics, techniques and case studies against AI systems | [3.17](../3-components/3.17-security.md) |
| Model pinning | Calling a specific model version rather than an alias that moves to newer versions | [3.7](../3-components/3.7-model-layer.md) |
| Model routing / cascade | Sending each request to the cheapest model likely to handle it, escalating hard ones to larger models | [2.1](../2-trade-offs/2.1-cost-quality-latency.md) |
| Multi-agent system | Several agents, each with its own instructions, tools and context, usually coordinated by a lead agent | [2.5](../2-trade-offs/2.5-single-vs-multi-agent.md) |
| Multi-hop question | A question whose later search depends on the answer to an earlier one | [3.5](../3-components/3.5-agentic-retrieval.md) |
| On-behalf-of identity | A tool call made with the end user's own scoped credentials, so the agent can't exceed the user's rights | [3.17](../3-components/3.17-security.md) |
| Orchestrator-workers | A model splits a task into subtasks decided at run time, hands them to workers and combines the results | [3.9](../3-components/3.9-workflows-and-agents.md) |
| Paged KV cache | Storing the KV cache in small fixed blocks, like OS memory pages, to avoid fragmentation (PagedAttention) | [3.8](../3-components/3.8-serving-internals.md) |
| Paired analysis | Comparing two versions on the same cases via per-case differences, which reduces noise | [3.15](../3-components/3.15-evals.md) |
| pass@k / pass^k | At least one of k attempts succeeds / all k attempts succeed | [3.15](../3-components/3.15-evals.md) |
| Post-filtering / pre-filtering | Applying a metadata filter after the vector search (can return too few results) or before/during it (keeps recall) | [3.6](../3-components/3.6-vector-stores.md) |
| Preference tuning (DPO) | Training on pairs of better and worse answers so the model favours the better kind | [3.18](../3-components/3.18-model-adaptation.md) |
| Prefill | The first phase of generation: the whole prompt is processed in one parallel pass, producing the first token | [3.8](../3-components/3.8-serving-internals.md) |
| Prompt caching | Provider-side reuse of a repeated prompt prefix, billed at a fraction of the input price | [3.13](../3-components/3.13-caching.md) |
| Prompt chaining | A fixed sequence of model calls, each working on the previous output, with checks in code between steps | [3.9](../3-components/3.9-workflows-and-agents.md) |
| Provisioned throughput | Reserved model capacity billed by time rather than per token, for steadier latency | [2.7](../2-trade-offs/2.7-throughput-vs-latency.md) |
| Quality bar | The agreed definition of a good output and how it is measured, set before the design | [1](../1-method/1-method.md) |
| Quantization (vectors) | Storing vectors in fewer bits (int8, binary, product codes) to shrink and speed up an index | [3.6](../3-components/3.6-vector-stores.md) |
| Quantization (weights) | Storing model weights or cache in fewer bits to cut memory and speed up decode | [3.8](../3-components/3.8-serving-internals.md) |
| Query fan-out | A model rewrites one question into several sub-queries that run in parallel and are merged; also query planning or decomposition | [3.5](../3-components/3.5-agentic-retrieval.md) |
| RAG | Retrieval-augmented generation: fetching relevant content and adding it to the prompt | [3.4](../3-components/3.4-retrieval-pipeline.md) |
| ReAct | Reason-then-act: the agent loop of thinking, calling a tool, observing the result and repeating | [3.9](../3-components/3.9-workflows-and-agents.md) |
| Recall (retrieval) | The share of the true relevant or nearest items that a search actually returns | [3.6](../3-components/3.6-vector-stores.md) |
| Reciprocal Rank Fusion (RRF) | Merging ranked lists by summing 1 / (c + rank) for each document, typically c = 60 | [3.4](../3-components/3.4-retrieval-pipeline.md) |
| Reinforcement fine-tuning (RFT) | Training on the model's own attempts, scored by a grader (code or a judge model) | [3.18](../3-components/3.18-model-adaptation.md) |
| Reranker | A model that re-scores (query, passage) pairs together to reorder a candidate set for precision | [3.4](../3-components/3.4-retrieval-pipeline.md) |
| Rug pull (MCP) | A tool server changes its tool definitions after they were reviewed and approved | [3.17](../3-components/3.17-security.md) |
| SAIF | Google's Secure AI Framework: a risk map over data, infrastructure, model and application, with controls | [3.17](../3-components/3.17-security.md) |
| Self-Route | Letting the model judge whether retrieved passages are enough to answer, falling back to the full context when they aren't | [2.3](../2-trade-offs/2.3-context-vs-retrieval.md) |
| Semantic caching | Returning a stored answer for a request whose meaning looks similar to an earlier one, by embedding similarity; no model call | [3.13](../3-components/3.13-caching.md) |
| Speculative decoding | A small draft model proposes tokens that the large model verifies in one pass; output is unchanged, decoding faster | [3.8](../3-components/3.8-serving-internals.md) |
| Step cap | A hard limit on how many model or tool calls an agent run may make before it stops or escalates | [2.2](../2-trade-offs/2.2-determinism-vs-autonomy.md) |
| Streaming | Returning output tokens as they are generated; improves perceived latency, not cost | [2.1](../2-trade-offs/2.1-cost-quality-latency.md) |
| Structured note-taking | An agent writes key facts and progress to a store outside the context window and reads them back later | [3.3](../3-components/3.3-context-engineering.md) |
| Sub-agent | An agent started by another agent to do one part of a task in its own context, returning a short summary | [2.5](../2-trade-offs/2.5-single-vs-multi-agent.md) |
| Supervised fine-tuning (SFT) | Training a model further on input-output examples of the desired behaviour | [3.18](../3-components/3.18-model-adaptation.md) |
| Token passthrough | An MCP server forwarding a client's token to another API without checking it was issued to the server; forbidden by the spec | [3.10](../3-components/3.10-multi-agent-and-protocols.md) |
| Tool pinning | Storing a hash of approved tool definitions and blocking or re-reviewing any that change | [3.17](../3-components/3.17-security.md) |
| Tool poisoning | Hidden instructions placed in a tool's description or schema, which the model reads and may follow | [3.17](../3-components/3.17-security.md) |
| Tool search | Loading tool definitions on demand by searching a catalog, instead of putting every tool in the context | [3.10](../3-components/3.10-multi-agent-and-protocols.md) |
| Tool-result clearing | Removing old tool results from the history once the agent has acted on them, often replacing each with a placeholder | [3.3](../3-components/3.3-context-engineering.md) |
| TPOT | Time per output token after the first; its inverse is output tokens per second | [2.7](../2-trade-offs/2.7-throughput-vs-latency.md) |
| TTFT | Time to first token: how long until the first output token arrives | [3.8](../3-components/3.8-serving-internals.md) |
| Workflow | Model calls connected by fixed code paths (chaining, routing, parallelization, orchestrator-workers, evaluator-optimizer) | [3.9](../3-components/3.9-workflows-and-agents.md) |

## Flashcards

Q: What does TTFT measure?
A: Time to first token: the delay before the first output token arrives, which sets perceived responsiveness when streaming.

Q: What distinguishes a workflow from an agent?
A: A workflow follows fixed code paths; an agent lets the model choose tools and steps in a loop.
