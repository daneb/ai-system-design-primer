# 3.10 Multi-agent topologies and protocols: deep dive

Reference material for [3.10 Multi-agent topologies and protocols](../3-components/3.10-multi-agent-and-protocols.md).
Read that first. Both protocols change quickly; check the dated specification you build against.

## MCP in detail

| Aspect | Detail | Source |
|---|---|---|
| Roles | Host (the AI app) runs one client per server; servers expose tools, resources and prompts; clients can offer sampling, elicitation and roots | [Spec](https://modelcontextprotocol.io/specification/2026-07-28) |
| Wire format | JSON-RPC 2.0 | Spec |
| Transports | stdio (local); Streamable HTTP (remote). HTTP+SSE deprecated since 2025-03-26 | Spec; [changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog) |
| Revisions | 2024-11-05, 2025-03-26, 2025-06-18, 2025-11-25, 2026-07-28 (current; removes sessions and the initialize handshake) | [Docs index](https://modelcontextprotocol.io/llms.txt); changelog |
| 2026-07-28 changes | Stateless: no `initialize` handshake or protocol sessions; version and client capabilities in every request's `_meta`; mandatory `server/discover`; server-initiated requests replaced by multi-round-trip results; tasks moved to an extension; OpenTelemetry trace context in `_meta`; Dynamic Client Registration deprecated in favour of Client ID Metadata Documents; 12-month deprecation policy | [Changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog) |
| Authorisation (HTTP) | Server is an OAuth 2.1 resource server; Protected Resource Metadata (RFC 9728) points to the authorisation server; clients MUST use PKCE (S256) and resource indicators (RFC 8707); servers MUST validate the token audience; token passthrough forbidden | [Security considerations](https://modelcontextprotocol.io/specification/draft/basic/authorization/security-considerations); [best practices](https://modelcontextprotocol.io/docs/tutorials/security/security_best_practices) |
| Governance | Donated by Anthropic to the Linux Foundation's Agentic AI Foundation (AAIF), December 2025, alongside OpenAI's AGENTS.md and Block's goose | [SD Times](https://sdtimes.com/ai/linux-foundation-forms-agentic-ai-foundation-to-be-new-home-for-mcp-goose-and-agents-md/) |

## A2A in detail

| Aspect | Detail | Source |
|---|---|---|
| Purpose | Agents built on different frameworks discover each other and delegate tasks without exposing memory, prompts or tools | [A2A spec](https://a2a-protocol.org/latest/specification/) |
| Discovery | Agent card at `/.well-known/agent-card.json` (renamed from `agent.json` in v0.3): name, description, version, supported interfaces (each with its own protocol version), capabilities, skills, security schemes; optional signatures | Spec; [release notes](https://github.com/a2aproject/A2A/releases) |
| Operations (v1.0) | SendMessage, SendStreamingMessage, GetTask, ListTasks, CancelTask, SubscribeToTask, GetExtendedAgentCard; create, get, list and delete push-notification config | Spec |
| Bindings | JSON-RPC, gRPC, HTTP+JSON/REST; `a2a.proto` normative | Spec |
| History | Announced by Google April 2025; Linux Foundation project June 2025; v1.0 on 12 March 2026 (v1.0.1 in May); joined AAIF August 2026 | [Release notes](https://github.com/a2aproject/A2A/releases); [A2A blog](https://a2a-protocol.org/latest/blog/2026/08/27/a-new-chapter-for-a2a-joining-the-agentic-ai-foundation/) |

## Risk and controls

| Risk | Reference | Control | Evidence an auditor would ask for |
|---|---|---|---|
| Tool poisoning: instructions hidden in tool descriptions | OWASP LLM01; ASI04 (agentic supply chain) | Approved server registry; pin and review tool descriptions; alert on changes | Registry; change log for tool metadata |
| Malicious or spoofed agent card | ASI07 (insecure inter-agent communication) | Verify signed cards; allow-list agents; mutual TLS | Agent allow-list; signature checks |
| Token passthrough / confused deputy | MCP spec; OAuth 2.1 | Audience-bound tokens; per-client consent in proxies; on-behalf-of flows | Token validation config; consent logs |
| Over-privileged local servers | Least privilege | Sandbox stdio servers; restrict file and network access | Sandbox policy |
| Unmonitored tool use | Audit | MCP/A2A traffic through a gateway; OpenTelemetry trace propagation | Gateway logs; traces ([3.16](../3-components/3.16-observability.md)) |
| Spec drift breaks clients | Operational | Pin protocol versions; test against `server/discover` | Version inventory |
