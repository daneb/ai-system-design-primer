# 3.11 Agent memory: deep dive

Reference material for [3.11 Agent memory](../3-components/3.11-memory.md). Read that first. Most
managed memory services are in preview; behaviour and pricing may change.

## What providers ship

| Provider | Service | Memory types | How it works | Source |
|---|---|---|---|---|
| AWS | Bedrock AgentCore Memory | Short-term (raw session events); long-term strategies: semantic (facts), summarisation, user preference, episodic, custom | Events written with `CreateEvent`; extraction runs asynchronously in the background (can take a minute); records stored in namespaces scoped by actor and session; `RetrieveMemoryRecords` does semantic search | [Long-term memory](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/long-term-memory.html); [harness memory](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/harness-memory.html) |
| Google | Vertex AI Agent Engine Sessions + Memory Bank | Facts about the user (topics configurable) | `generate` extracts facts from a session asynchronously with Gemini; consolidation creates, updates or deletes memories, including on contradiction or an explicit "forget"; memories keyed by a scope (up to 5 key-value pairs); similarity search; purge by scope | [Memory Bank quickstart](https://docs.cloud.google.com/agent-builder/agent-engine/memory-bank/quickstart-api) |
| Microsoft | Foundry Agent Service memory (preview, Nov 2025) | User profile; chat summary; procedural | Memory store with a chat and an embedding model; `user_profile_details` steers what to extract (Microsoft's example excludes age, financials, precise location and credentials); TTL setting; retrieve profile early, summaries per turn; billed via underlying model usage during preview | [What is memory](https://learn.microsoft.com/azure/foundry/agents/concepts/what-is-memory); [how to](https://learn.microsoft.com/azure/foundry/agents/how-to/memory-usage) |

## Where they agree

- **Separate short-term (session) from long-term memory.**
- **Extract asynchronously** so writes don't slow the user's turn.
- **Scope memories** to a user or actor; never share across scopes.
- **Consolidate** rather than append (Google and Microsoft explicitly).

## Where they differ

- **Who decides what to store.** Managed services extract automatically with a model you configure;
  Anthropic's memory tool lets the agent decide and gives you the storage.
- **Procedural memory.** Microsoft extracts reusable routines; AWS offers custom strategies; others
  leave procedures to instructions and skills.

## The research

- **CoALA (Sumers et al., 2023)** sets out working, episodic, semantic and procedural memory for
  language agents, and warns that letting agents write procedural memory (their own code or rules) is
  riskier than writing facts.
- **MemGPT (Packer et al., 2023)** treats the context like an operating system's main memory, with the
  agent paging facts in and out via tools.
- **Mem0 (Chhikara et al., 2025; vendor paper)** reports extraction plus consolidation beating
  full-context replay on the LOCOMO benchmark with 91% lower p95 latency and over 90% fewer tokens, and
  26% better than OpenAI's ChatGPT memory on an LLM-judge score. A competitor disputes the comparison;
  treat vendor benchmarks with care.
- **Benchmarks:** LOCOMO and LongMemEval test recall across many sessions, including updates and
  time-based questions.

## Risk and controls

| Risk | Reference | Control | Evidence an auditor would ask for |
|---|---|---|---|
| Memory poisoning from untrusted content | OWASP ASI06 (memory and context poisoning); LLM01 | Write only from trusted sources; record provenance; review or quarantine memories derived from tool output | Provenance fields; poisoning tests |
| Cross-user leakage | OWASP LLM02; data protection | Scope by user ID from the authenticated session, never from the prompt; tests for cross-scope reads | Scope design; access tests |
| Excessive personal data retained | Data minimisation (GDPR, POPIA) | Exclusion lists for sensitive categories; TTLs; purpose limitation | Retention config; data inventory |
| Right to access and erasure | GDPR, POPIA | User-visible memory; delete and purge by scope | Deletion logs; DSAR process |
| Stale memory drives wrong action | Model risk | Consolidation; timestamps; confirm before acting on old memories | Multi-session evals |
| Agent rewrites its own rules | CoALA; ASI | No agent writes to procedural memory without review | Change control on instructions and skills |
