## What providers ship

| Provider | History management | Tool-result handling | Notes and memory | Source |
|---|---|---|---|---|
| Anthropic | Server-side compaction (summarise and drop); client-side SDK compaction | Context editing: `clear_tool_uses` clears oldest tool results past a threshold (default trigger 100k input tokens, keeps 3), replaced by a placeholder; `clear_thinking` for thinking blocks | Memory tool; Claude is warned before clearing so it can save notes | [Context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing) |
| OpenAI | Agents SDK sessions; cookbook trimming (last N turns) and summarising sessions; Responses API chains state with `previous_response_id` but does not manage size for you | (your code) | Session stores | [Cookbook](https://developers.openai.com/cookbook/examples/agents_sdk/session_memory) |
| Google (ADK) | Context compaction: sliding window (interval + overlap) or token threshold, summarised by a model and written back to the session | Working context is rebuilt per call from session events | Memory service; artifacts kept outside the prompt | [ADK compaction](https://adk.dev/context/compaction/); [Google blog](https://developers.googleblog.com/architecting-efficient-context-aware-multi-agent-framework-for-production/) |

## Where they agree

- **Context is finite and degrades before it fills.** All frame it as a budget.
- **Two basic moves:** drop old content (trim, clear) or replace it with a summary. Every framework
  ships both.
- **Keep recent turns verbatim.** Summarisers in ADK, Strands and Microsoft preserve the latest
  messages raw.
- **Don't split a tool call from its result.** Microsoft's reducers and third-party compaction for the
  OpenAI SDK both cut at safe points.

## Where they differ

- **Server vs client.** Anthropic offers compaction and clearing in the API; the others do it in the
  SDK or your code.
- **Storage vs view.** Google's ADK separates durable session state from the per-call "working
  context", a compiled view of it. This keeps a full record for audit while sending the model less.
- **What gets summarised.** Microsoft leaves function calls out of summaries; Anthropic clears tool
  results first and leaves the conversation.

## The research

- **Context rot** (Chroma, 2025): 18 models tested; all became less reliable as input grew, even on
  simple tasks. Similar but irrelevant text (distractors) made it worse. Near-perfect needle-in-a-haystack
  scores hide this.
- **Lost in the middle** (Liu et al., TACL 2024): accuracy follows a U-shape over position; relevant
  documents in the middle are used least. Later work links it to positional attention bias.
- Both say the same thing for design: curate and order, don't fill.

## Risk and controls

| Risk | Reference | Control | Evidence an auditor would ask for |
|---|---|---|---|
| Agent forgets a user constraint or policy | Model risk | Keep instructions and policies pinned; notes for key facts; long-session evals ("what did the user ask on turn 1?") | Eval results on long sessions |
| Poisoned content persists across turns | OWASP LLM01; ASI06 (memory poisoning) | Clear or quarantine untrusted tool results; don't summarise instructions from untrusted data into trusted memory | Provenance tags on context items |
| Sensitive data copied into summaries and memory | Privacy; data minimisation | Redact before summarising; retention rules for summaries | Data-flow records; retention config |
| Can't reconstruct what the model saw | Audit; model risk | Log the working context per call, or its sources and transformations | Trace samples ([3.16](../3-components/3.16-observability.md)) |
