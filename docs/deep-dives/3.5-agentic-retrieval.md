# 3.5 Agentic retrieval: deep dive

Reference material for [3.5 Agentic retrieval](../3-components/3.5-agentic-retrieval.md). Read that
first. This is a frontier topic: features are in preview and the evidence is mixed.

## What providers ship

| Provider | Feature | How it works | Source |
|---|---|---|---|
| Microsoft | Azure AI Search agentic retrieval (knowledge bases; preview) | An LLM reads the query and conversation history and writes sub-queries; they run in parallel (keyword, vector or hybrid) and are reranked; a reasoning-effort setting goes from *minimal* (no LLM planning) to *low* (one planning pass, default) to *medium* (deeper search). Each knowledge base is also an MCP server. Billed per token, not per query. | [Overview](https://learn.microsoft.com/azure/search/agentic-retrieval-overview); [retrieve](https://learn.microsoft.com/azure/search/agentic-retrieval-how-to-retrieve) |
| AWS | Bedrock Knowledge Bases query reformulation (2024) and agentic retrieval | Reformulation breaks a query into sub-queries; agentic retrieval plans the retrieval and can expand to the full document when a passage lacks context (needs `GetDocumentContent` permission as well as `Retrieve`) | [What's new](https://aws.amazon.com/about-aws/whats-new/2024/07/knowledge-bases-amazon-bedrock-advanced-rag-capabilities); [AWS blog](https://aws.amazon.com/blogs/machine-learning/agentic-retrieval-with-langchain-and-amazon-bedrock-knowledge-bases/) |
| Google | Vertex AI RAG Engine as an ADK tool; Vertex AI Search | Retrieval exposed as a tool the agent calls; ADK's RAG tool must be the only tool on its agent (use a sub-agent) | [ADK RAG Engine tool](https://google.github.io/adk-docs/integrations/vertex-ai-rag-engine) |
| OpenAI | `file_search` hosted tool in the Responses API | Semantic and keyword search over vector stores; the model decides when to call it; result count and metadata filters configurable | [File search](https://developers.openai.com/api/docs/guides/tools-file-search) |
| Anthropic | Agentic search (guidance); Claude Code uses glob, grep and file reads | Keep lightweight references (paths, queries) and load data just in time with tools; Anthropic suggests starting with agentic search and adding semantic search if you need speed | [Context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) |

## Where they agree

- **Decompose complex questions.** Microsoft and AWS both ship query decomposition into sub-queries.
- **Retrieval as a tool**, not a fixed pre-step, in every agent SDK.
- **Read more than a chunk** when needed: AWS expands to the whole document; Anthropic opens files.

## Where they differ

- **Index or no index.** The cloud platforms build on a managed vector or hybrid index. Anthropic's
  coding agent dropped embeddings for grep and file reads; secondary sources report OpenAI's and
  Cline's coding agents do the same, while Cursor combines grep with a trained embedding index.
- **Planned vs looped.** Azure's default is one planning pass with parallel execution (fast,
  predictable); agent loops are open-ended.

## The evidence is mixed

- **For loops:** multi-hop questions need them (see the lab). Anthropic reports agentic search
  outperformed its earlier RAG for Claude Code, but by its own account on "mostly vibes" plus internal
  benchmarks (secondary source: interview with Boris Cherny).
- **Against:** an August 2026 empirical study of repository-level code questions found semantic search
  answered 65.2% correctly against 46.2% for deep agentic search (grep by sub-agent), at under half the
  cost per correct answer; failures often ended in a fluent, confident wrong answer
  ([arXiv 2608.01507](https://huggingface.co/papers/2608.01507)).
- **Research patterns:** Self-RAG trains the model to decide when to retrieve and to critique results;
  Corrective RAG adds a lightweight evaluator that grades retrieved documents and triggers a rewrite or
  web search; Adaptive RAG routes by question complexity.
- **Take-away:** measure on your questions. Route by type rather than making every query agentic.

## Risk and controls

| Risk | Reference | Control | Evidence an auditor would ask for |
|---|---|---|---|
| Retrieved content injects instructions | OWASP LLM01; ASI01 | Treat results as data; Rule of Two ([2.4](2.4-capability-vs-security.md)); limit actions after reading untrusted content | Tool permissions; injection tests |
| Agent retrieves content the user can't see | OWASP LLM02; data protection | Enforce the user's permissions in every retrieval tool (security trimming), not in the prompt | Access tests per tool |
| Partial evidence, confident answer | Model risk | Require citations; "not found" path; evaluate retrieval recall and stop decisions | Eval reports on multi-hop sets |
| Runaway search cost | OWASP LLM10 | Round and token caps; route lookups to single-shot | Cost per question by type |
| Full-document expansion widens access | Least privilege | Scope document-read permissions as tightly as search | IAM policy review |
