## Governance

| Risk | Control | Evidence |
|---|---|---|
| Wrong answer relied on for a customer decision | Citations shown with every answer; "check the source" UI; correctness and citation evals with thresholds | Eval reports per release; sampled production scores |
| Disclosure of restricted policies | Pre-filtered retrieval; separate sensitive indexes; permission suite | Permission test results; access-filter code review |
| Stale or withdrawn policy cited | Change feed; effective dates; withdrawn documents removed within an agreed time | Index freshness monitor; sample audits |
| Model or provider change degrades quality | Paired evals gate every change; pinned model versions | Change log with eval deltas |
| Misuse or data in logs | Masking; access control; retention | Logging configuration; access reviews |

## Building it on each platform

The design is vendor-neutral; each platform offers managed pieces. Check permission filtering first,
because it decides whether a managed index is usable at all.

| Piece | Azure | AWS | Google Cloud | OpenAI | Anthropic | Open source |
|---|---|---|---|---|---|---|
| Managed index, hybrid search | Azure AI Search (RRF) | Bedrock Knowledge Bases | Vertex AI RAG Engine | File search with vector stores | — (bring your own; contextual retrieval recipe) | OpenSearch, Elasticsearch, PostgreSQL + pgvector |
| Reranking | Semantic ranker | Bedrock reranker models | Ranking API | Built-in reranking | — | Cross-encoders |
| Permission-aware retrieval | Document-level access: security filters; Entra and SharePoint ACLs (preview) | Metadata filtering | — (not verified) | — (not verified) | — | Filter fields enforced by the app |
| Gateway | AI gateway in API Management | LiteLLM-based gateway guidance; AgentCore Gateway (not verified here) | Apigee | — | — | LiteLLM, Envoy AI Gateway |
| Grounding check | Groundedness detection | Contextual grounding checks | Check grounding API | Guardrails library hallucination check | Quote-and-verify pattern | Judge model |
